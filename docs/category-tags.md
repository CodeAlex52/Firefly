# 博客分类与标签规范

> 写作时对照本文件填写文章 frontmatter。分类和标签无需额外配置，写了即自动出现在分类页/标签页/首页分类导航。

## 一、分类体系（每篇文章只选 1 个）

| 分类 | 用途 | 示例 |
|---|---|---|
| 前端 | 前端技术：HTML/CSS/JS/TS、框架、构建工具、前端性能 | "Vue 响应式原理"、"Tailwind v4 踩坑" |
| 后端 | 服务端：语言、API 设计、业务逻辑、中间件 | "Go 切片详解"、"Gin 中间件实现" |
| 网络 | HTTP/HTTPS、DNS、TCP、CDN、代理、抓包 | "HTTPS 握手全过程"、"Cloudflare IP 优选原理" |
| 数据库 | SQL/NoSQL、Redis、索引、数据迁移 | "MySQL 索引失效场景"、"Redis 缓存雪崩" |
| 运维与部署 | Linux、Docker、CI/CD、云服务、监控 | "博客部署到 Cloudflare Workers" |
| 工具与效率 | Git、编辑器、命令行、AI 工具、开发环境 | "我常用的终端命令"、"用 Obsidian 写博客" |
| 架构与设计 | 系统设计、设计模式、重构、代码质量 | "单点登录（SSO）设计" |
| 技术随笔 | 行业观察、技术思考、面试经验 | "聊聊技术博客要不要写" |
| **待分类** | **临时桶：暂时没想好归类的文章先放这，想好后移到上面合适的分类** | — |

## 二、标签规则（每篇 2~3 个）

**公式：统一阶段词 + 具体技术词**

| 标签类型 | 说明 | 示例 |
|---|---|---|
| 统一阶段词 | 全站统一，跨技术复用 | `基础语法` `框架` `踩坑` `实战` `性能优化` |
| 具体技术词 | 这篇文章的技术名，长期积累成系列入口 | `Vue` `Go` `Redis` |

示例：

```yaml
category: 后端        # 领域分类，1 个
tags: [基础语法, Go]  # 统一阶段词 + 具体技术词
```

### 规则清单

1. **每篇 2~3 个标签**，最多不超过 5 个
2. **系列必打**：围绕同一个技术写多篇时，技术名标签每篇都打（如 15 篇 Vue 文章都打 `Vue`），标签页点一下就是整个系列
3. **不打与分类重复的标签**（分类是"前端"就不打"前端"标签）
4. **用词必须统一**：同一概念永远用同一个词（"组件通信"不要有时写"组件间通信"）
5. **孤品标签要清理**：一个标签只有 1 篇文章用，说明它是文章关键词而不是标签，删除或合并。经验法则：标签应被至少 2~3 篇复用
6. 标签体系是**自然生长**的，不用提前规划完整表，写作时按规则打即可

## 三、frontmatter 模板

```yaml
---
title: 文章标题
published: 2026-08-17
category: 前端
tags: [基础语法, Vue]
description: 文章简介（选填）
---
```
